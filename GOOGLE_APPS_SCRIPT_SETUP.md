# ZATONA request form: Google Apps Script integration

The bilingual three-step form posts to the existing Apps Script web app. The endpoint URL is public configuration; the spreadsheet and its credentials must remain private.

## Request and confirmation

The browser sends an `application/x-www-form-urlencoded` POST with a `payload` parameter containing a JSON string. It follows the Apps Script redirect and reads the JSON response using CORS. The UI shows success only after receiving readable JSON with `success: true`; an initiated request, opaque response, invalid JSON, HTTP error, or timeout is not treated as success.

The JSON payload contains exactly these application properties:

```json
{
  "companyName": "Company",
  "industry": "technology",
  "companySize": "startup",
  "companyWebsite": "",
  "contactName": "Contact",
  "jobTitle": "founder",
  "email": "contact@example.com",
  "phone": "+201000000000",
  "requestedService": "social_media_management",
  "requestedPackage": "basic",
  "estimatedBudget": "egp_3000_5000",
  "projectSummary": "A project summary with at least twenty characters.",
  "language": "en",
  "website": ""
}
```

`website` is the honeypot and must remain empty for legitimate submissions. The browser does not send a serial number or timestamp. A separate URL-encoded `submissionToken` is sent as retry metadata, not as a JSON property. The form blocks concurrent/double-click submissions. If a timeout makes it impossible to know whether the server saved the request, the form preserves its values and tells the visitor to contact ZATONA before retrying. The backend should use the token to make retries idempotent.

## Existing spreadsheet contract

The existing merged headings in row 1 and headers in row 2 must never be changed. Client submissions start at row 3. Apps Script may write only columns A:M:

| Column | Value |
|---|---|
| A | Automatic serial number generated by Apps Script |
| B | Company Name |
| C | Company Industry |
| D | Company Size |
| E | Company Website |
| F | Contact Person Name |
| G | Job Title |
| H | Email |
| I | Phone |
| J | Requested Service and Package |
| K | Estimated Budget |
| L | Project Summary |
| M | Submission date/time generated by the server |

Service and package are sent separately and should be combined in column J. The form's additional advertising-budget choice is included as a clearly labeled line in `projectSummary`, because the agreed payload has no separate advertising-budget property. Do not write to columns after M.

## Endpoint configuration

The active public endpoint is set once in [assets/js/config.js](./assets/js/config.js):

```js
window.ZATONA_CONFIG = {
  appsScriptUrl: "https://script.google.com/macros/s/AKfycbx3Qjgl6jTR3Kmvpt-afHC0Q5IiVjbU65DgCStO8-2WuehAvn3A_tliZ6xhQAMqutrgRg/exec"
};
```

The URL is public by design. Do not put a spreadsheet URL, spreadsheet ID, OAuth token, or service-account key in this file.

## Important Apps Script source warning

The repository's `google-apps-script/Code.gs` is an earlier implementation: it expects a different flat-field request, writes a 17-column schema, and returns an iframe `postMessage` response. It does **not** implement the current `payload` JSON request or the A:M sheet contract above. Do not deploy that file over the supplied live Apps Script endpoint. The deployed endpoint's source must be updated separately by its owner if its behavior or idempotency needs changes.

## Live verification

Use clearly marked synthetic information, never actual client data. After submitting from the published site:

1. Confirm the response is readable JSON with `success: true` before treating the form as successful.
2. Confirm exactly one matching test row was added starting at row 3, with server-generated serial and timestamp in A and M.
3. Confirm rows 1–2 and every column after M are unchanged.
4. Verify canonical values and the correct `language` on both English and Arabic pages.
5. Test a rapid double-click and a failure/timeout. The form should not show false success and must keep entered values.
6. Remove test rows only with the spreadsheet owner's approval.

An HTTP 200 response by itself does not prove a row was saved. The private spreadsheet must be checked to verify the server's write and confirm that it touched only columns A:M.

## Local checks

The repository's earlier Apps Script source has Node.js mock tests:

```sh
node --test google-apps-script/Code.test.js
```

These tests cover that earlier source only. They do not verify the supplied live endpoint, its A:M schema, or a real Google Sheet.
